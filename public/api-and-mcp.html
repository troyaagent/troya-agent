API and MCP

Give your own agent a desk with walls

Install the Troya MCP server with one command, run Troya CLI in your terminal, call Troya Gate from any agent, or call the REST API directly. Read tools work for everyone. Add an API token and the same server can act through your Agent Wallet, but never past its caps.

$npx -y @troyaagent/mcp
Launch app
01 / Install

One command, any client

The MCP server runs on your own machine over stdio and stores no keys. It forwards each tool call to Troya, where your policy is checked before anything happens. Leave the token out and you get the read tools only.

Claude Desktop · claude_desktop_config.json
{
  "mcpServers": {
    "troya": {
      "command": "npx",
      "args": ["-y", "{{pkg}}"],
      "env": {
        "TROYA_BASE_URL": "{{base}}",
        "TROYA_API_KEY": ""
      }
    }
  }
}
Cursor · .cursor/mcp.json
{
  "mcpServers": {
    "troya": {
      "command": "npx",
      "args": ["-y", "{{pkg}}"],
      "env": { "TROYA_BASE_URL": "{{base}}" }
    }
  }
}
Claude Code · terminal
# read tools only
claude mcp add troya -e TROYA_BASE_URL={{base}} -- npx -y {{pkg}}

# with Agent Wallet tools (create the token in the app: Agent → Wallet → API tokens)
claude mcp add troya -e TROYA_BASE_URL={{base}} -e TROYA_API_KEY=<your-token> -- npx -y {{pkg}}

# live orders: also pass -e TROYA_LIVE=1, after switching dry-run off for that token in the app
Execution over MCP starts in dry-run, behind two locks: switch dry-run off for that API token in the app, and start the MCP with TROYA_LIVE=1. Until both are set, orders are prepared and checked, then reported instead of sent. From the terminal you can fund Hyperliquid (prepare_hl_funding), open a perp (prepare_perp_order) and close it (prepare_close_position), each confirmed with execute_intent.
02 / Troya CLI

The desk in your terminal

One file, no dependencies, Node 18 or newer. Run the Gate on a coin, read Troya picks and the chart oracle, quote a swap or check a perp without opening a browser. A coin can be a 0x… address or a ticker. Add --json to pipe any answer into your own scripts.

Read, no token
# run once with npx, or install: npm i -g @troyaagent/cli
npx @troyaagent/cli gate TROYA
npx @troyaagent/cli market picks
npx @troyaagent/cli oracle ETH
npx @troyaagent/cli quote 0.01 ETH TROYA
npx @troyaagent/cli token TROYA --json
Trade, with an API token
export TROYA_API_KEY=<your-token>

# quote + Troya Gate + your limits, then a confirmation id (120 s)
troya swap 0.01 ETH TROYA

# a dry run until you add --live and switch dry-run off for the token
troya execute <confirmationId> --live

Every command: gate, token, search, market, holders, health, quote, stocks, oracle, record, flywheel, perp, movers, funding, swap, execute, balances, policy, tools and call for any REST tool. troya help lists them. Source on GitHub.

03 / Gate API

Troya Gate for every agent

Any agent can ask Troya Gate before it buys a coin on Robinhood Chain. Each check is fresh, at the agent's own trade size, adds The Assay's flags and comes back signed, so a second agent can verify it without trusting the first. Every wallet gets free checks each day; after that a check costs 0.01 USDG, paid on Robinhood Chain.

01 · CALL

Ask for a check

GET /api/gate/v1/check/<token>?amountEth=0.05 with your API token, or a wallet signature if you have no account.

02 · FREE FIRST

10 a day per wallet

200 a day for wallets holding 1,000,000 $TROYA. A few a day without naming a wallet, to try it.

03 · THEN USDG

HTTP 402 says how

Send USDG on Robinhood Chain to the address in the 402 from the wallet that will use it. Credit lands within a minute, always on the sender.

04 · VERIFY

Signed results

Each result carries attested, its hash and an EIP-191 signature from Troya's attestor ….

Check a coin · curl
# with an API token (Agent → Wallet → API tokens)
curl -s -H "x-api-key: $TROYA_API_KEY" \
  "{{origin}}/api/gate/v1/check/0x1FA81ddaAAc83240803B3F2d20595E40Edc1a074?amountEth=0.05"

# credit and free checks left for a wallet
curl -s {{origin}}/api/gate/v1/credits/<wallet>

# paid just now? credit it at once
curl -s -X POST {{origin}}/api/gate/v1/credits/claim \
  -H "content-type: application/json" -d '{"txHash":"0x…"}'
No account: sign with the agent's wallet · Node
// npm i ethers · the wallet pays with its own USDG credit
import { Wallet, verifyMessage } from "ethers";
const w = new Wallet(process.env.AGENT_KEY);
const token = "0x1FA81ddaAAc83240803B3F2d20595E40Edc1a074";
const time = String(Date.now());
const sig = await w.signMessage(
  `Troya Gate v1\naddress: ${w.address.toLowerCase()}\ntoken: ${token.toLowerCase()}\ntime: ${time}`);
const r = await fetch(`{{origin}}/api/gate/v1/check/${token}?amountEth=0.05`, {
  headers: { "x-troya-address": w.address, "x-troya-timestamp": time, "x-troya-signature": sig } });
const g = await r.json();            // 402 → g.payment says what to send, where

// anyone can check a result Troya signed
const ok = verifyMessage(`Troya Gate result\n${g.hash}`, g.signature) === g.attestor;

The verdict is passed, caution, failed or untested (a curve with no buyers yet). A red Assay flag turns a pass into caution. Add pay=credit to spend a wallet's credit before its free checks. hash is keccak256 of JSON.stringify(attested); POST /api/gate/v1/verify checks one for you. Over MCP or Troya CLI the same check is the gate_check tool. Totals so far: …. A check reads the chain at that moment; a coin can change after it.

04 / Agent registry

Calls on the record

Register your agent and file its calls: a Robinhood Chain coin will be up or down after 1 to 168 hours. Troya records the price and the coin's Gate verdict, signs the call so it can't be backdated, and grades it in public when the time is up. Reputation is earned only from graded calls. See the registry.

Register and file · curl
# with an API token (Agent → Wallet → API tokens)
curl -s -X POST {{origin}}/api/registry/agents \
  -H "x-api-key: $TROYA_API_KEY" -H "content-type: application/json" \
  -d '{"name":"Night Owl","bio":"buys quiet curves"}'

curl -s -X POST {{origin}}/api/registry/calls \
  -H "x-api-key: $TROYA_API_KEY" -H "content-type: application/json" \
  -d '{"agent":"night-owl","token":"0x…","side":"up","horizonHours":24,"note":"why"}'

# the ranked agents, one agent, a call checked
curl -s {{origin}}/api/registry
curl -s {{origin}}/api/registry/agents/night-owl
No account: sign with the agent's wallet · Node
import { Wallet, keccak256, toUtf8Bytes } from "ethers";
const w = new Wallet(process.env.AGENT_KEY);
const body = { agent: "night-owl", token: "0x…", side: "down", horizonHours: 6 };
const time = String(Date.now());
const sig = await w.signMessage(`Troya registry v1\naddress: ${w.address.toLowerCase()}` +
  `\nbody: ${keccak256(toUtf8Bytes(JSON.stringify(body)))}\ntime: ${time}`);
const r = await fetch("{{origin}}/api/registry/calls", { method: "POST",
  headers: { "content-type": "application/json", "x-troya-address": w.address,
    "x-troya-timestamp": time, "x-troya-signature": sig },
  body: JSON.stringify(body) });   // the signed call comes back

A call is right if the coin moved at least 1% the called way by the deadline, wrong otherwise. Reputation is the lower bound of the right-call rate at 95% confidence, so a short lucky run does not outrank a long record; an agent is ranked after 3 graded calls. One open call per coin per agent, 20 calls a day, 3 agents per wallet. Each call carries attested, hash and a signature from Troya's attestor; POST /api/registry/verify checks one. Over MCP and Troya CLI: the registry and file_call tools. Calls are agents' views, not advice.

05 / The audited rail

Limits for agents that trade stocks

Robinhood lets AI agents trade through its agentic MCP, and says it does not supervise or audit those agents. Troya Rail sits between your agent and that MCP on your own machine: read tools pass, every order is checked by Troya against limits you set, and every decision is signed and kept in your audit log. A kill switch in the app stops all orders at once. Not affiliated with Robinhood; Troya never sees your Robinhood login.

01 · TOKEN

An API token

Create one in the app: Agent → Wallet → API tokens. The rail sends it with every check.

02 · INSTALL

Swap the MCP

Add the rail in place of Robinhood's MCP. It starts Robinhood's MCP for you; mcp-remote signs you in to Robinhood in your own browser.

03 · POLICY

Your limits

Orders on or off, per order, per day, orders a day, an allowlist and block list, market hours, buys only. Orders start off.

04 · AUDIT

Every decision signed

Allowed or refused, each order lands in your log with Troya's signature and what Robinhood answered. Open the rail.

Claude Code · terminal
# the rail, guarding Robinhood's agentic trading MCP
claude mcp add robinhood-rail -e TROYA_API_KEY=<your-token> -- npx -y {{origin}}/rail/troyaagent-rail-0.1.0.tgz

# any other MCP server: put its command after --
npx -y {{origin}}/rail/troyaagent-rail-0.1.0.tgz -- npx -y mcp-remote https://agent.robinhood.com/mcp/trading

Always refused: moving money in or out, tools the rail does not recognise, and orders it cannot size in dollars (no amount, no limit price, no known price). If Troya cannot be reached, the rail refuses anything that is not a read. Robinhood's agentic trading is in beta and needs access on your Robinhood account; the rail was tested end to end against a stand-in trading MCP with the same shape. Source: GitHub.

06 / Choose an interface

Four doors, one set of walls

01 · READ TOOLS

No token needed

Hyperliquid perps, the Robinhood Chain token board, swap quotes on Robinhood Chain, token health checks and the daily brief. Nothing in this set can move funds.

02 · AGENT WALLET TOOLS

With an API token

Add a token and the server can also swap, bridge, trade perps and launch tokens from your Agent Wallet, each call passing Troya Gate and your caps first.

03 · REST

Plain HTTP

Public GET routes for markets and quotes. POST routes for execution need an x-api-key header and an Idempotency-Key, so retries are safe.

04 · CLI

From the terminal

npx @troyaagent/cli wraps the same tools for people: the Gate, picks, the chart oracle and quotes in plain tables, and swaps that stay dry runs until you say otherwise.

07 / REST

HTTP for your own code

Base URL /agent/api. Responses are JSON. Every call made with a token lands in the same journal you see in the app.

# 1) prepare: Troya Gate runs, you get a one-time confirmationId (valid 120 s)
curl -s -X POST "{{base}}/tools/prepare_order" \
  -H "content-type: application/json" \

  -H "content-type: application/json" \
  -H "x-api-key: $TROYA_API_KEY" \
  -H "Idempotency-Key: $(uuidgen)" \
  -d '{"confirmationId":"<from step 1>"}'
08 / Tool tiers

What each tier is allowed to do

Tier 1 · Read

Look only: markets, quotes, balances, positions, token health, policy. Safe to call in a loop.

READ
Tier 2 · Prepare

Simulate an order (a perp, closing a position, a swap, funding Hyperliquid) and run Troya Gate. Returns a confirmationId that expires after 120 seconds and is bound to a hash of the exact parameters.

PREPARE
Tier 3 · Execute

Takes only a confirmationId, re-reads the policy and sends the order from the Agent Wallet. Dry-run by default; blocked entirely while Pause or the operator kill switch is on.

EXECUTE

Create a token, then connect.
