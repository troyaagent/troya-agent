Agent Wallet changelog

Every change to the code that decides or signs Agent Wallet trades, newest first: the date, what changed, which files, how it was tested and the commit.

Real-money tests on VerifyRisk controls
Changes to Agent Wallet signing code ship only with tests and an entry here.

Signing code means the files that decide whether an Agent Wallet trade goes out and that sign it: server/agentwallet.mjs, server/policy.mjs, and the Gate checks those files call before a buy (server/tools.mjs, server/robinhood.mjs). The rule starts with this page on 24 Nov 2026. The earlier entries below are taken from the repository history and say how each change was tested at the time, including where no automated test was committed. Commit hashes refer to the Troya source repository.

Last updated 24 November 2026

Chiron rules on Agent Wallet buys

24 Nov 2026

The owner's own Chiron habit rules (no buys in a coin's first N seconds, at most N buys a day) are now checked on every Agent Wallet buy. They apply to buys only; a sell is never held back by them. A rule that cannot be checked refuses the buy instead of letting it through.

Changed
  • checkAction takes a side. For a swap with side buy it calls chiron.ruleCheck and adds its reasons; a caller that leaves the side out gets exactly the checks of before.
  • New swapSide: ETH, WETH or USDG in and any other coin out is a buy, the reverse is a sell.
  • The Agent Wallet works out the side before checkAction. A creator buying the coin it launched through Troya from the same Agent Wallet (the initial buy, the dev panel) is not counted as a buy for these rules.
  • A buy that was broadcast counts towards the "buys a day" rule (chiron.noteBuy).
Files
server/policy.mjs, server/agentwallet.mjs, server/chiron.mjs (new), server/tools.mjs (the prepare-swap tool passes the side)
Tested
tools/chiron-test.mjs, 24 unit checks with the chain mocked, among them: no rule set lets a buy pass as before; a coin younger than 60 seconds is blocked and an hour-old one passes; an age that cannot be read fails closed; a sell is never held back; after two buys the third is blocked when the rule is two a day. Re-run on 24 Nov 2026: 24 of 24 pass. No real-money test of this change is listed on Verify.

Launch ring check in the Gate

24 Nov 2026

Asked for by Xivor. For a buy of any Pons coin, the Gate adds a Launch ring line from Ring Radar: how many wallets were freed from the snipe tax at launch and how much of the supply the dev and those wallets took in the first blocks. A red launch fails the Gate for a buy, so the Agent Wallet does not sign it. A sell is never blocked by it: on a sell the same finding is a warning.

Changed
  • gateCheck reads the Ring Radar line beside the quote and adds it only when the swap is a buy.
  • gateSwap adds it for Pons coins, passing whether the swap sells.
  • The line itself (ringradar.gateLine): red is a fail on a buy and a warning on a sell; a read still running after the wait is a warning; a coin with no Pons launch found gets no line. The launch is now found at any age through the Blockscout log index, with the RPC search of the last two days as the fallback.
Files
server/robinhood.mjs, server/tools.mjs, server/ringradar.mjs
Tested
No automated test was committed with this change.

Coin withdrawals from the Agent Wallet

21 Nov 2026

Coins bought by Sentry Autopilot, Champions, the War Table or Aegis can be withdrawn. Before this, only ETH could leave, so those coins were stuck.

Changed
  • An ERC-20 transfer whose recipient is always the owner's own address, never an address from the request.
  • "all", or no amount, sends the whole balance; a typed amount is cut at the coin's decimals and never above what is held.
  • Withdrawals to the owner do not count against the trading caps.

Lot ledger and one Budget

21 Nov 2026

The Agent Wallet keeps a lot ledger: which automated job holds which coins and how each lot closed, so a job's sell is sized to its own coins and its result is measured in ETH. The caps that apply are shown as one Budget.

Changed
  • One lot-aware swap at a time per owner, so two jobs exiting the same coin cannot both read the balance before either sold.
  • Sell amounts are kept to 15 significant digits, cut and never rounded up, so a sell never asks for more than the wallet holds.
  • A balance below the open lots is read again before any coins are counted as sold elsewhere (a public RPC can be a block behind right after a buy).
  • getBudget (read-only): the strictest of the operator caps, the user's own limits and the wallet's caps, and which one binds. It changes no limit.

Trust ladder: Approve by default, held proposals stay held

20 Nov 2026

A wallet that never picked a trust step now starts on Approve: every automated trade waits for the owner's yes. Before, an unset ladder meant Auto.

Changed
  • DEFAULT_TRUST is approve; an explicit choice is kept as it is.
  • A held proposal carried by an automated job (the browser-tab Autopilot) goes through only on Auto. Before, a proposal id skipped the ladder, so the tab could execute the trades Approve had just held.
  • The job a request speaks for keeps its name all the way down, so the ladder and that job's own daily cap apply to it; only the owner's own tap counts as "app".

Balances read every coin the wallet holds

Found by the first War Table real-money test: the balance reader listed only WETH and USDG, so the Sell buttons saw nothing to sell and a wallet holding only memecoins counted as empty for the delete guard.

fa566ee

Scepter: trust ladder and per-job daily caps

20 Nov 2026

Automated jobs (Autopilot, playbooks, Aegis and the rest) follow a trust ladder: on Watch they only alert, on Approve they ask first, on Auto they act inside the caps. A trade the owner taps or confirms is never held back by the ladder.

Changed
  • The ladder is enforced in the Agent Wallet for the named automated jobs (AUTO_JOBS).
  • Each job has its own daily cap inside the wallet's caps, with what each job spent today counted per job.
Files
server/agentwallet.mjs, server/policy.mjs
Tested
Real money, 20 Nov 2026: with the ladder on Auto, a DCA job bought and a TWAP job sold in two slices, each through the Gate and the caps; one slice reverted on chain and was logged (Verify, step 39).

Perps: fund the missing margin, then open

19 Nov 2026

Asked for in the community. When the owner's Hyperliquid account is short of margin, the Agent Wallet funds the shortfall from Robinhood Chain to the owner's own Hyperliquid account, and the order opens by itself once the USDC lands.

Changed
  • New action perp_funded with a pending opener. The order runs through the normal perp path when it opens, so the Gate, the caps and the kill switch apply again at that moment.
  • The pending opener gives up after 20 minutes and says so in the inbox; it never runs twice.
  • The funding itself does not count against the caps; the perp counts when it opens.
