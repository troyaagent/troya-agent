The walls, in detail

Every limit lives in policy, outside the model. Every action is tested against it before it runs and written down after it runs. Here is what that means in practice.

Set your limits in the app
01 / Brakes

Three ways to stop

Stopping should never be harder than starting. Each brake works on its own, and none of them needs the agent's cooperation.

01

Pause

One switch in the app. While it is on, your Agent Wallet cannot sign anything and running playbooks are held. Turning it off again is your call alone.

02

Dry-run

Over MCP, execution starts in dry-run: orders are prepared, checked and reported, not sent. You switch it off per API token when you are ready.

03

Kill switch

The operator can halt every execution path at once, for every user, if something looks wrong with a venue, a contract or the service itself.

02 / Who holds what

Know where each key sits

There are up to three keys in play. Only one of them is held by the operator, and it is the one you are told to keep small.

Your wallet

Held by you
  • Troya never sees or stores its key.
  • Every action needs your signature in the wallet itself.
  • Disconnect at any time; nothing keeps running in its name.

Agent Wallet

Held by the operator, encrypted
  • Optional and custodial: treat it like pocket money.
  • Acts only inside your daily caps and leverage cap.
  • Withdrawals go only to your own connected address.
  • You can export its key whenever you like.
  • Never touches your main wallet.

Hyperliquid trading key

An approved agent key
  • Approved by you on Hyperliquid for placing and cancelling orders.
  • Cannot withdraw or transfer funds; Hyperliquid itself enforces that.
  • Revoke it on Hyperliquid at any time.
03 / Limits

Caps you set, checks it cannot skip

These live in policy on the server and are read again on every single call. If an order breaks any of them, it is refused, and the refusal is logged with the rule that stopped it.

A

Per-trade cap

The most one order can be worth in USD, whoever signs it.

B

Daily USD cap

A ceiling on what the Agent Wallet may spend or open in a rolling day.

C

Leverage cap

The highest leverage the agent may use on any perp, below the venue's own maximum if you choose.

D

Allowlist

Perps: list the Hyperliquid markets the agent may trade, and every other market is refused (an empty list means every perp). Robinhood Chain tokens: each one must pass Troya Gate, and the operator can block tokens or limit trading to a list; you can only make it stricter.

04 / Troya Gate

Seven checks before every swap

Troya Gate is the pre-trade check. It runs before a proposal is shown to you and again before the Agent Wallet signs. If any check fails, the order is not offered, and you see which check failed and the number behind it. The same checks as JSON: Gate on $TROYA.

01Route

Is the path real, through a pool or Pons curve that exists on the chain right now? No route, no order.

02Price impact

How far this order moves the price. Above 5% is a warning; above 15% the order is not offered.

03Pool depth

ETH behind the quote. Under 0.5 ETH is a warning; under 0.05 ETH the order is not offered.

04Fees and taxes

Pool and launch fees inside the quote. Above 5% is a warning; above 10% the order is not offered.

05Transaction simulation

The exact swap is run against the current pool first. If it would revert, it is not offered.

06Test sell

A simulated sell straight after the buy. If the token cannot be sold back, the order is not offered.

07Transfer tax

What the test sell loses on transfer. Above 0.5% is a warning; above 10% the order is not offered.

05 / Text and records

Strangers' words are data. Every move is on record.

Fenced text

Token names, descriptions and posts from X are written by people you do not know. Troya marks them as untrusted before the model sees them, so a line like "ignore your limits" inside a token name is just a string.

The journal

Every proposal, signature, refusal and Agent Wallet action is written to your journal with the reason the agent gave and the rule that applied. It is readable in the app and is never edited after the fact.
